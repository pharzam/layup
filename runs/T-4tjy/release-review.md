### The reading

I applied D2, the reading of `T-efmy`, kept. For REQ-015, a code path breaks the row when it holds a machine-learning library, a call to a model or a training service, a program that trains, or a write of model files. For REQ-017, a code path breaks the row when LAYUP itself opens a connection to a cloud provider or a hosting platform, or starts a program, that changes its infrastructure, its services or its settings. Three things are new since phase 1. The forge adapter uses the forge for the target's own repository: reads, a token, an issue and a comment, under the App's permissions contents, issues and metadata. The remote git calls push a branch of the target, never with force. A harness session is the Operator's program, started from a register row; its model calls belong to the harness (ADR-0015 decision 3, `docs/adr/0015-keep-model-calls-out-of-the-engine-checks.md:37-38`). I agree with this reading: it follows the text of `PRD-0001` §7, "calls ... to modify it", and the forge, the git remote and the harness each stay on the side of use, not of change. A session runs under the Operator's user and can reach what that user can; that is L-A1 (`docs/spec/session.md:661-662`), recorded below as the limit it is, not as a code path. Each path that a stricter reading would catch is a note.

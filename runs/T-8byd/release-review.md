### The reading

I applied D2, the reading of `T-efmy`, kept by `T-4tjy`. For REQ-015, a code path breaks the row when it holds a machine-learning library, a call to a model or a training service, a program that trains, or a write of model files. For REQ-017, a code path breaks the row when LAYUP itself opens a connection to, or starts a program for, a cloud provider or a hosting platform to change it. Four things are new since `M2b`. A session of a phase is the same harness program, started at the same two sites, with an input directory and one output file. The span check and the budget of milestone 0 are code that calls nothing. The comments of the Intake issue are read with `Comments` and written with `Comment`, the two forge calls that `M2b` had, on the target's own issues. The rest is records. I agree with the reading: it follows the text of `PRD-0001` §7 ("calls ... to modify it"); the forge, the git remote and the harness each stay on the side of use, not of change; and a session of a phase is a harness session like a task session, whose model calls belong to the harness (ADR-0015 decision 3). A session runs under the Operator's user and can reach what that user can. That is L-A1 (`docs/spec/session.md`), a limit, not a code path, recorded as finding 13. Each path that a stricter reading would catch is a note. No finding names a defect: none is fixed on the path, and none opens an issue.

# T-hbw8 — deep check, the author's own pass

Claude Opus 5.5 (the author), 2026-09-28, written before the author read the two reviewers' outputs.

M = material, N = note.

1. M — Disagreement stalls are not detected. PSB stall = "role agents do not agree, or a step repeats without progress". ADR-0013 d5 detects only no-progress by clock and N retries. A reviewer/implementer ping-pong makes new commits and handoff rows each round, so it is "progress" and never stalls. Fix: a disagreement = the same review finding or a `material` verdict repeated after K fix cycles (parameter) → stall.
2. M — Mid-session questions have no mechanism. How does a running harness session ask, pause and get the answer? Headless sessions exit; the answer needs a new session for the owner role, then a new session that continues the asker's work with the answer. Not described. Also: PSB Clarification Turnaround target ≤120 s p95 cannot be met by starting a reasoning-model session per answer (our sessions take 5–16 min). Fix: describe the flow (ask → exit with a question record → owner session → resume session with the answer in its prompt file); state turnaround as a known limit against the start value.
3. M — Question routing lacks "needs a human decision". PSB Problem 1 root cause names three unknowns: the kind, the owner, and whether it needs a human. The Choice has no "business-forking" option; the escalation screen applies to decisions, not questions. Fix: each question passes the escalation screen before routing.
4. M — The escalation floor "in code" is overclaimed. ADR-0018 d1: "A decision that changes a number of the budget file, a line of the approved problem statement, or a Must requirement is business-forking with no model call." A decision written in prose cannot be checked by code; only a proposed diff touching `budget.tsv`, the facts or a Must row can. Also the screen reads the agent's own list of its choices (self-declaration, the PSB root cause). Fix: floor = diffs touching those files; prose → the four questions; state self-declaration as a known limit, caught by the Missed Escalations audit.
5. M — Fact numbering is overclaimed (same class as psb check). ADR-0020 d1: "`layup` stores … with a record that numbers each clause as a fact". Splitting prose into clauses is semantic; LAYUP's own F-0001/F-0003 were numbered by a task session. `layup spec draft` "one requirement row per In-Scope fact" assumes code can find the In-Scope section — only if the PSB has a fixed "In Scope" heading. Fix: a role session numbers the clauses, `check facts`-style code verifies byte-exact substrings; the In-Scope rule needs a PSB format check (a gap rule) or a human-confirmed list.
6. M — Intake writes to the records branch before it exists. §4 Intake writes `approvers.tsv`, `budget.tsv`; the target repo and `layup-records` are created in Scaffold. Fix: create the repository and the records branch first (start of Intake), or state where Intake records live.
7. M — Per-task budget estimates at Intake are impossible. ADR-0018 d2: idea owner writes "per task an estimate" at Intake; tasks exist only after Plan. Fix: idea owner sets milestone B/U at Intake; task estimates come from the Plan phase, inside B.
8. M — Handoff schema validation is not defined. PSB 7.1 "100% schema-validated state artifacts across all role transitions" (REQ-005). ADR-0016 gives a `valid` column but no schema: allowed transitions per phase/role, required artifact kinds, which linter validates each artifact. Fix: define the transition table and the artifact checks (a register `transitions.tsv`).
9. M — Reversal has no record. ADR-0019's reward counts "a reversal" and PSB §7.2 Reversal Rate needs it; no table has a reversal column. Fix: `reversed_by` / `reversed_at` in `questions.tsv` and `decisions.tsv`, written by the audit.
10. M — The dead-man job is overclaimed. ADR-0013 d6: the scheduled job "notifies the Operator with a stall package". A job in LAYUP's repository on GitHub has only the pushed heartbeat and records, not the host's evidence; scheduled workflows run at ≥5-minute intervals, can be delayed, and need a token to read each target. Fix: it opens a stall issue with the last pushed rows; the package is built by `layup run` on restart.
11. N — Vision 3.1 context routing is claimed in name only (§9.4: "the prompt file names the records a session reads"). No mechanism selects or prunes context. Mark partial or add a per-role context manifest.
12. N — Vision 3.3 reward omits "verification scores" and "token/time efficiency"; ADR-0019's reward has no cost term. Add cost and verifier-finding terms (parameters). "Test pass rates" conflict with F-0003#58 — say so.
13. N — Vision 3.1 names "Jev and Laya"; Laya is never researched or mentioned. State it.
14. N — Vision 3.4 "exclusively through issues": the design deviates (Git tables); §9.4 should say "deviation, by Invariant 1", not "answered".
15. N — Gate Integrity "0 agent writes to rule paths" vs the retrospective batch that an agent writes. Fix: the orchestrator commits the approved batch; the audit counts rule-path writes outside an approved batch.
16. N — Stall Decision Point 5: "The Operator can … give the task to a different harness agent" — no mechanism for that override. Add: an Operator comment with a harness ID, copied into Git, overrides the route.
17. N — `layup gate` "from outside" needs each target stack's toolchain on the LAYUP host.
18. N — `layup spec check` fails "an In-Scope fact has no Must row": code sets a priority, which is an intent decision of the idea owner (PSB Out of Scope). Fix: the idea owner confirms priorities at the Architect approval.
19. N — Next milestone restarts at Design: an architecture approval each milestone; human load.

## Verdict
**Borrow the pattern.** AO is a mature Go supervisor of harness CLIs, and we ran it headless on the toy Go target. Its state lives in SQLite outside the project's Git (I1), it has no rule protection, no gates and no escalation rule, and LAYUP is standard library only. So LAYUP should copy its patterns: the harness launch adapters, the hook-based activity facts, the derived status, the report (question) protocol, and the merge preconditions bound to the head SHA. LAYUP should not run or link the program.

## What it is (from the code)

The links below point to the pinned SHA. Short form: `<path>:<line>`.

- **A long-running daemon with a thin CLI.** The CLI calls the daemon over loopback HTTP, and `ao daemon` is the hidden entry point ([docs/cli/README.md:1](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/docs/cli/README.md#L1), [backend/internal/cli/root.go:339](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/cli/root.go#L339)). At this SHA, `ao start` does not start the daemon. It downloads the desktop app (about 177 MiB) from GitHub releases.
- **State.** All state is in SQLite (146 goose migrations) under `~/.ao`, which `AO_DATA_DIR` can move ([CLAUDE.md:5](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/CLAUDE.md#L5)). The only durable session facts are the activity state, the terminated flag and the PR facts. The display status is never stored ([docs/architecture.md:33-45](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/docs/architecture.md#L33)).
- **Worktree per session.** AO runs `git -C <repo> worktree add` on branch `ao/<session>/root` ([backend/internal/adapters/workspace/gitworktree/commands.go:35-43](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/adapters/workspace/gitworktree/commands.go#L35)). The worktrees are under `AO_DATA_DIR/worktrees/<project>/<session>`.
- **How it drives harness CLIs.** One adapter per harness, 28 in all (`backend/internal/adapters/agent/*`). One argv builder maps a neutral permission policy to each CLI's flags. Examples: Claude `--permission-mode bypassPermissions`, Codex `--dangerously-bypass-approvals-and-sandbox`, `--session-id`, `--model`, `--effort`, and the prompt after `--` ([backend/pkg/agentruntime/command.go:94](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/pkg/agentruntime/command.go#L94)). This package imports only the standard library and `google/uuid`. The Claude launch is at [claudecode.go:165](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/adapters/agent/claudecode/claudecode.go#L165). AO puts its hooks into the worktree's `.claude/settings.local.json`. They report SessionStart, UserPromptSubmit, the tool events, PermissionRequest, Stop and SessionEnd back to the daemon as `ao hooks claude-code <event>` ([hooks.go:42-68](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/adapters/agent/claudecode/hooks.go#L42)). Before launch, `PreLaunch` writes a trust entry into the host's `~/.claude.json` ([claudecode.go:210](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/adapters/agent/claudecode/claudecode.go#L210)).
- **Roles and prompts.** The role prompts are Go string templates: the orchestrator ([prompt.go:191](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/session_manager/prompt.go#L191)), the worker ([prompt.go:250](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/session_manager/prompt.go#L250)) and the reviewer ([backend/internal/review/prompt.go:17-52](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/review/prompt.go#L17)). Each project can add rules inline or from a repo-relative file (`agentRulesFile`), and can override the harness and model per role and per reviewer ([backend/internal/domain/projectconfig.go:38-60](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/domain/projectconfig.go#L38)). The orchestrator is an LLM session. It writes each worker's task prompt.
- **Board state.** [backend/pkg/contract/status.go:102-133](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/pkg/contract/status.go#L102) derives the status from the facts. The UI groups the statuses: "Needs you" = needs_input, exited, no_signal, ci_failed, changes_requested; "In review" = pr_open, draft, review_pending; "Ready to merge" = approved, mergeable, merged ([packages/product-ui/src/session-presentation.ts:437-460](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/packages/product-ui/src/session-presentation.ts#L437)). - **Worker reports (the question path).** The command is `ao report --checkpoint|--needs-input|--stuck|--done` ([prompt.go:293-303](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/session_manager/prompt.go#L293)). Needs-input and stuck reports are available at once. A done report waits a fixed 5-minute settlement window ([backend/internal/service/report/service.go:111-118](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/service/report/service.go#L111), [backend/internal/domain/report.go:49](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/domain/report.go#L49)). A stuck report can interrupt the orchestrator at most once each 3 minutes per worker ([backend/internal/service/report/coordinator.go:20](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/service/report/coordinator.go#L20)). AO delivers reports only to an active orchestrator session. It never starts one.
- **Loops and nudges.** On a CI failure, AO sends the failure to the worker once per new failure signature, with no attempt limit. A review comment is sent at most 3 times ([backend/internal/lifecycle/reactions.go:18](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/lifecycle/reactions.go#L18), [:275](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/lifecycle/reactions.go#L275), [:300](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/lifecycle/reactions.go#L300), [:1025](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/lifecycle/reactions.go#L1025)). At the cap, AO stops sending. It writes no stall record and no diagnosis. The runtime reaper probes liveness every 5 seconds ([backend/internal/observe/reaper/reaper.go:21](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/observe/reaper/reaper.go#L21)).
- **Review.** The auto-review starts after a worker is idle for 1 minute, with at most 3 retries per PR head ([backend/internal/autoreview/coordinator.go:15-23](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/autoreview/coordinator.go#L15)). A review run is keyed by PR URL and head SHA ([backend/internal/review/planner.go:40](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/review/planner.go#L40)). The reviewer posts a GitHub review with `gh api`, always as `COMMENT`. It then gives AO a machine verdict (`approved` or `changes_requested`) through `ao review submit` ([review/prompt.go:27-39](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/review/prompt.go#L27)).
- **Merge.** `ao pr merge` refuses the merge when the head is not the expected SHA, when CI is failing, pending or unknown, when a change request or an unresolved human thread is open, or when the PR is not mergeable. It merges with **squash** ([backend/internal/service/pr/action_service.go:95-154](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/service/pr/action_service.go#L95), [backend/internal/domain/pr.go:242-258](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/domain/pr.go#L242)). The worker agent opens the PR because its prompt tells it to. AO does not open it.
- **Usage.** AO reads token usage from the harness transcript and stores it per session and model, with an estimated cost (`model_usage_events`, `GET /api/v1/usage/sessions/{id}`). The session is marked incomplete only when an integrity row exists ([backend/internal/storage/sqlite/queries/usage.sql:607-610](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/storage/sqlite/queries/usage.sql#L607)).

## What we ran

All work was under `eval-work/ao/`. The environment was `HOME=eval-work/ao/home`, `AO_DATA_DIR`, `AO_RUN_FILE`, `AO_PORT=3137`, `AO_TMUX_SOCKET_NAME=ao-eval` and `AO_TELEMETRY_*=off`. `GH_TOKEN` and `GITHUB_TOKEN` were unset. `GIT_CONFIG_GLOBAL` pointed to a file in the work directory. The fake HOME held one symbolic link to the user's keychain directory, so that `claude` could authenticate. The target was `toy/`: a Go module with package `calc`, one test and a `Makefile` (`go vet`, `go test`), and `remote.git` as a local bare remote.

1. **Clone and build.** `git clone --depth 1` at the SHA above. Then `go build -o bin/ao ./cmd/ao` with GOPATH and GOCACHE in the work directory. The build took 31 seconds and made a 41 MB binary.
2. **Start.** `ao doctor`: PASS for git, tmux, claude-code, opencode, agy, devin, kiro. `ao start` began to download "Agent Orchestrator (agent-orchestrator-darwin-arm64.zip, ~176.9 MiB)". I stopped it and started `ao daemon` directly. `ao status`: `AO daemon: ready ... readyz: ready`. **The daemon runs headless without the desktop app.**
3. **Project.** `ao project add --path toy --id toy`, then `ao project set-config toy --model claude-haiku-4-5-20251001 --permission bypass-permissions --reviewer claude-code`. Note: `set-config` replaces the whole config, so it dropped the `--worker-agent` value from `project add`.
4. **Run 1 (toy-1) and run 2 (toy-2): failed.** Claude Code in the fresh HOME stopped at its first-run dialogs (onboarding, then the bypass-permissions warning). AO showed `idle`, then `no_signal` after 90 seconds (in the "Needs you" group). AO did nothing else. `--mode chat` failed: `chat driver unavailable: AO ACP runtime is not installed`. That runtime ships with the desktop app.
5. **Run 3 (toy-3): worker, passed.** I wrote a small websocket client for the terminal mux (`/mux`, handle `ptyhost-v1:toy-3`), read the screen, and accepted the dialog. The worker then added `Sub` and its test, ran `make check`, committed `986ee61 feat(calc): add Sub function for subtraction`, pushed `ao/toy-3/root` to the bare remote, and ran `ao report --done`. The `reports` row: `state=done ... delivery_state=pending`. No orchestrator existed, so the report stayed pending.
6. **Run 4 (toy-4 orchestrator) and run 5 (toy-5 worker): the question path, passed.** The orchestrator prompt said: delegate `Mul` to one worker; the worker must first ask "Name it Mul or Multiply?" with `ao report --needs-input`; answer with `ao send`. Its done report stayed `pending` until 13:01:24Z, which is the 5-minute settlement window. The earlier toy-3 report was delivered in the same batch when the orchestrator became active.
7. **Run 6 (toy-6): token accounting, passed.** In runs 3 to 5, Claude Code showed "Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker", because I started the daemon from inside a Claude Code session. A review needs a GitHub or GitLab PR, and the brief forbids a GitHub write. I read the review and merge code instead (see above).

## Deep-check findings it answers

- **Fable-M16 (who chooses the role and prompt of each step):** partly, as a pattern. AO has fixed role templates in code (orchestrator, worker, reviewer) plus project rules from a repo-relative file (`agentRulesFile`). An LLM orchestrator writes each task prompt. LAYUP can use the same split: role templates as target content, and a task prompt from the planning role. AO has no task class.
- **Sol-27 (PR creation and review step):** partly, as a pattern. The review run is bound to PR URL and head SHA. The reviewer returns a machine verdict next to the forge review. The merge checks the expected head SHA, green CI, no change request, no unresolved human thread, and mergeable. AO does not enforce PR creation (only the prompt asks for it). It merges with squash, which LAYUP forbids.
- **Author-2 (path of a mid-session question):** yes, as a pattern, and observed. The worker stays alive and writes a durable report (`needs_input`). The daemon delivers it at once to the coordinator session. The coordinator answers with `ao send` into the same live session, and the worker continues. There is no exit and no resume. Measured: 0.6 s delivery, 34 s from question to done. Limit: with no active coordinator, the report waits.
- **Fable-M5 (the clock opens a stall at each wait for a human):** yes, as a pattern. AO separates `waiting_input` and `blocked` (a wait for a person) from `no_signal` (no hook signal), and treats only the second as trouble ([docs/architecture.md:39](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/docs/architecture.md#L39)).
- **Fable-M4 (disagreement is never a stall):** partly. Review nudges are capped at 3 per thread, and a repeated identical CI failure signature is not sent again. A capped loop ends in silence ("Needs you"), not in a stall record.
- **Sol-22 (a new record resets the stall clock):** partly. AO counts attempts per key and signature, not per new artifact ([reactions.go:1025](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/lifecycle/reactions.go#L1025)).
- **Fable-M22 and Author-16 (move a task to another harness):** partly, as a pattern. `ao session switch-agent <id> codex` keeps the worktree and hands over a bounded handoff record.
- **Fable-N3 and Sol-11 (the unit of telemetry):** partly. The unit is one session. Tokens come from the harness transcript and are priced per model. This is a working pattern for "action = session".
- **Sol-28 (time of the accepted answer):** partly. `reports.created_at` and `acknowledged_at` are stored. No acceptance event exists.
- **Sol-23 (model allocation by complexity):** no. The model is set per project, per role or per spawn. The orchestrator prompt says to add `--model` only when the human or the task asks ([prompt.go:225](https://github.com/Untrivial-ai/agent-orchestrator/blob/3ed3aff8e017d11accc3099e30134355ce8da4e5/backend/internal/session_manager/prompt.go#L225)).
- **Fable-M23 (host user-level setup):** no. AO runs the harness with the host's HOME and writes `~/.claude.json`. Our run showed that a clean HOME with only a keychain link works, and that the harness then needs its first-run dialogs pre-answered.
- **Fable-M1, M2, Sol-1 (rule protection):** no.

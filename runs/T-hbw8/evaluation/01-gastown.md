## Verdict

**Borrow the pattern** for the watchdog layers, the per-item attempt caps, the merge-request record and the session start by a "prime" hook. **Reject** Gas Town as a program to run next to LAYUP and as vendored code. The work state lives in a Dolt server and in files of the town, not in the project's Git (Invariants 1 and 2). The merge gate and the stall judgement are prose that an LLM follows, and an empty gate passes (Invariants 5 and 6).

## What it is (from the code)

Gas Town is a "town" directory with a Mayor, a Deacon and per-project "rigs". Each rig has a Witness, a Refinery and short-lived "polecat" workers. Each agent is a harness session in its own tmux session. Work items are Beads issues in a Dolt database that `gt` starts.

- **Sessions.** `StartSession` builds a tmux `new-session` with `GT_ROLE`, `BD_ACTOR` and `GIT_AUTHOR_NAME` in the environment, and gives a one-line "beacon" as the first prompt ([internal/session/lifecycle.go#L144](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/session/lifecycle.go#L144), [internal/session/startup.go#L84](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/session/startup.go#L84)). The real context comes from `gt prime --hook`, which the harness's SessionStart and PreCompact hooks run ([internal/hooks/config.go#L1069](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/hooks/config.go#L1069)). Mail goes in through a UserPromptSubmit hook `gt mail check --inject` ([internal/hooks/config.go#L1091](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/hooks/config.go#L1091)). Nudges are tmux `send-keys` in 512-byte chunks ([internal/tmux/tmux.go#L1607](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/tmux/tmux.go#L1607)). The default Claude command is `claude --dangerously-skip-permissions` ([internal/config/agents.go#L233](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/config/agents.go#L233)); there are 13 presets ([internal/config/agents.go#L25](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/config/agents.go#L25)).
- **Startup dialogs.** `gt` reads the pane text and presses Enter on the workspace trust dialog, on the assumption that "the safe continue option is pre-selected" ([internal/tmux/tmux.go#L2004](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/tmux/tmux.go#L2004)). Liveness is the process name in the pane ([internal/tmux/tmux.go#L2421](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/tmux/tmux.go#L2421)).
- **Work assignment.** `gt sling` puts a bead on an agent's "hook" (status `hooked`, assignee the agent) and bonds a workflow "formula" to it. A per-bead file lock stops a double sling ([internal/cmd/sling.go#L1290](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/cmd/sling.go#L1290)). The daemon's convoy loop feeds ready beads again and again.
- **Mail and handoff.** Mail is a bead with label `gt:message` in the town database ([internal/mail/router.go#L218](https://github.com/gastownhall/gastown/blob/649b832b7672bc7a2dbef26f5983aba6198b819b/internal/mail/router.go#L218)). ## What we ran

All under `eval-work/gastown/`. `gt` ran through a wrapper with `env -i`, `HOME=eval-work/gastown/home`, `GT_TMUX_SOCKET=gteval`, no `GH_TOKEN`.

1. **Install.** Dolt 2.3.5 binary from the GitHub release into `prefix/bin`. `go build ./cmd/gt` at the pin, and `go build ./cmd/bd` for Beads. Both built with no error.
2. **Toy target.** `toy/`: a Go module, one package `calc`, one test, `make check` = `go vet` + `go test`. A local bare remote `remote.git`.
3. **Version skew (failed).** `gt install town --git --dolt-port 33977` with bd 1.3.0 (Beads `main`) gave: `refusing to auto-apply 20 pending schema migrations to a shared server database (v49 -> v69)`. I rebuilt bd at v1.0.5 (the version in Gas Town's `go.mod`, which its CI installs). Then the install passed.
4. **Rig.** `gt rig add toy file://.../remote.git --prefix toy`. It made `.repo.git`, a refinery worktree, a mayor clone and rig beads. `gt rig settings set toy merge_queue.test_command "make check"`.
5. **Agent.** I overrode the built-in `claude` agent with a wrapper that runs Claude Code with `--model claude-haiku-4-5-20251001 --setting-sources project,local`. The wrapper must be named `claude`: with the name `claude-eval`, the liveness check did not match the process name and killed the session (`session toy-obsidian unhealthy during startup: agent-dead`).
6. **First slings (failed).** `gt sling toy-2ar toy` failed: `startup blocked: interactive startup dialog still visible in toy-obsidian: workspace trust prompt`. The pane showed Claude Code's trust dialog with `❯ No, exit` pre-selected, so Gas Town's Enter would exit. I set `CLAUDE_CODE_SANDBOXED=1` in the wrapper to skip the dialog without a write to `~/.claude.json`.
7. **Retry cap (seen).** After 3 failed spawns the daemon log said: `sling toy-2ar failed: Error: spawning polecat: respawn limit reached for toy-2ar (3 attempts). This bead keeps failing — investigate before re-dispatching.` The convoy loop kept trying every 30 s and logged the same error. `gt sling respawn-reset toy-2ar` cleared it.
8. **The task.** The daemon's convoy fed `toy-2ar` ("Add Mul to calc") to polecat `obsidian`. It followed `mol-polecat-work` (load context, branch, implement, commit, self-review, build check, pre-verify, submit). `gt done` failed twice: `cannot complete: uncommitted changes would be lost`, because Gas Town's own files (`.beads/`, `.claude/`, `.runtime/`, `CLAUDE.md`) were untracked in the worktree. The agent then committed a new `.gitignore` for them into the project (commit `1e2dc53 chore: add .gitignore for polecat runtime files`). No one asked for this change.
9. **Dead-agent recovery (seen).** The first Refinery session had lost its agent (my wrapper rename). Its pane was a bare shell that had received the nudge text as a command: `zsh: command not found: MERGE_READY`. The Witness mailed the Mayor `Cycle 9: Refinery session down`. At the next heartbeat the daemon logged `Refinery session for toy started successfully`. It also logged `Mayor agent not detected (cycle 2/3), waiting before restart` (a 3-cycle confirmation).
10. **Merge (seen).** The new Refinery took the merge request `toy-wisp-60c`, ran `make check 2>&1 | head -50`, reviewed the diff ("Score: 0.95, recommendation: approve") and pushed `d23c431 Merge polecat/obsidian/toy-2ar+mul96un3 into main` straight to `main`. The `| head -50` hides the exit code of `make check`; the agent judged the output. The formula variables were not filled in (`**Config: test_command = {{test_command}}**`); the agent found `make check` in the settings file.
11. **Spawn storm (seen).** The Refinery's own patrol steps became ready beads (for example `toy-wfs-z7h3e "Check refinery mail"`, owner `toy/refinery`), and the daemon slung them to new polecats `jasper`, `onyx`, `opal`, `topaz`, `garnet`. `gt down --polecats` stopped most sessions, but a new polecat started during the shutdown; I killed the `gteval` tmux server.
12. **Escalation.** `gt escalate -s high "Eval: reviewer and author disagree on toy-2ar" -r "..."` made bead `hq-wisp-62o` (labels `gt:escalation, severity:high`, fields `source`, `related_bead`, `reescalation_count`, all free text or null) and mail to the Mayor. It printed `email action 'email:human' skipped: contacts.human_email not configured`.
13. **Independence check.** A plain `git clone` of `remote.git`: `make check` passes. The clone has the code, the `.gitignore` and the agent authors (`obsidian`, `toy/refinery`). It has no issue, no merge request, no mail, no escalation and no cost: these are in `town/.dolt-data/{hq,toy}` (5.2 MB each) and in `~/.gt/costs.jsonl`.
14. **Cost record.** `~/.gt/costs.jsonl` had `hq-deacon ... "cost_usd":1.7131` after 2 minutes. From the transcript tokens, the whole Deacon history (3 sessions) is about 1.03 USD at the Haiku 4.5 price: Gas Town priced Haiku 4.5 as Sonnet. Later records were `0`, probably because `gt` looked for transcripts under the redirected HOME.

## Deep-check findings it answers

- **Sol-22** (a new record resets the stall clock): partly. The per-bead respawn cap (spawn_count.go#L92) and the re-dispatch cap (redispatch.go#L23) count attempts on one work item, whatever new artifacts appear. Pattern: an absolute attempt cap per task, separate from progress events.
- **Author-10 and Sol-4** (the dead-man job): partly, as a pattern. A local Go daemon ticks every 3 minutes, restarts dead agents with backoff, and stops at a crash loop until a human clears it (restart_tracker.go#L44). `gt install --supervisor` adds launchd/systemd. This supports "the package is built by the local orchestrator on restart", not a job on GitHub.
- **Fable-M5** (the clock runs during a human wait): partly. Worker states `awaiting-gate`, `paused` and `stuck` stop cleanup (status.go#L44), but the GUPP timer does not stop. Pattern: an explicit wait state that the watchdog skips.
- **Sol-27 and Fable-M9** (no PR step): partly. With `merge_strategy = "pr"` the Refinery opens a PR, watches the checks and can require an approval (formula #L680); the merge-request bead binds the branch to a commit SHA. The default is a direct push, and there is no issue link.
- **Fable-M3** (commits do not show the agent): partly. Each session gets `GIT_AUTHOR_NAME` = the agent name (env.go#L23); the run shows authors `obsidian` and `toy/refinery`.
- **Fable-M4, Author-1** (disagreement is never a stall): none. The Refinery-to-polecat `FIX_NEEDED` loop has an attempt number with no cap and no comparison.
- **Fable-M6** (no diagnosis before the Operator): none. No automatic fresh-context examiner.
- **Fable-M12, Sol-3** (one writer): none. Many agents write to a shared database; only the Refinery merges to `main`.

## Where the searchers were wrong or incomplete

- Searcher B: "merges to main using a Bors-style bisecting queue". The Bors code exists but no production code calls it. The running merge is a Claude session that follows a formula, and by default it pushes straight to `main`.
- Searcher B: "runs verification gates". Only when the rig sets commands; the default is empty and "skip silently". The Refinery agent ran the gate through `| head -50`.
- Searcher B: "autonomous stall detection". True for dead or hung sessions; nothing detects disagreement; some thresholds are fixed constants and some config readers are not wired.
- Searcher B: "Last push 2026-09-18". The API says so, but the last commit on `main` is 2026-07-23. Gas Town pins Beads v1.0.5 (2026-05-28); Beads `main` (1.3.0) cannot open the database that Gas Town makes.
- Searcher A: "git issues". The issues are in Dolt, not in Git.
- Both did not say that Gas Town writes into `$HOME` (`~/.gt`, `~/.beads`, `~/.dolt`, `~/.config/bd`) and into each worktree (`CLAUDE.md`, `.claude/`, `.beads/`, `.runtime/`), or that its patrol agents cost money when no work is waiting.
- Both are right that the state is outside the project repository (I1, I2) and that Gas Town is a pattern, not a base.

## Limits of this evaluation

- Only Claude Code (Haiku 4.5) was run. The other 12 presets were not run.
- The GUPP (30 minutes) and Deacon (20 minutes) timers did not fire; I read their code. I stopped the town after about 10 minutes to limit cost.
- `merge_strategy = "pr"` and the email/SMS routes were not run: they need writes to network services.
- Claude Code ran with the real HOME (for its login) and `CLAUDE_CODE_SANDBOXED=1`; `gt` and `bd` ran with a redirected HOME. Two early hook calls wrote `~/.gt/costs.jsonl` and `~/.gt/cmd-usage.jsonl` in the real HOME; I copied them to `eval-work/gastown/evidence/` and removed `~/.gt`. A `dolt version` call made `~/.dolt`; I removed it. Claude Code added two project entries (trust `false`) to `~/.claude.json` for the town paths, as any Claude Code run does; I did not edit that file.
- The spawn storm and the unfilled formula variables can come from the version pair (gt `main` at 649b832 with bd v1.0.5). I did not test other pairs.
- Processes stopped: all `gteval` tmux sessions (server killed), the `gt` daemon, the `gt nudge-poller`, the town Dolt server on port 33977 (checked free). No container was used.

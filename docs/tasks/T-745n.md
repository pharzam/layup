## Decisions

- **D1.** Rules 1 to 3 of #70 are the check `adapted` of
  [`setup/setup-check.sh`](../setup/setup-check.sh), with fixtures under
  `docs/setup/tests/adapted/`; rule 4 is the check `markers`, made stricter. The
  `pre-commit` hook runs `sh docs/setup/setup-check.sh --only adapted,markers .`
  (added last, when the tree passed, condition 1). CI runs both in the job
  `setup-check`.
- **D2.** The check reads the tracked Markdown files, except the records and the
  fixtures: `docs/facts/`, `runs/`, `docs/tasks/T-*.md`, `docs/tasks/completed.md`,
  the accepted ADRs `0001` to `0012`, `docs/setup/record-*.md`, the fixture
  directories `docs/{adr,ci,links,prd,setup}/tests/`, `.githooks/tests/`,
  `internal/psb/testdata/`.
- **D3.** The word lists are in the check's header comment. Rule 1 exempts the
  check names `kit-history` and `kit-linters` only (round 1, finding 4, removed a
  general exemption of `-kit`), and matches the plurals `kits` and `templates`.
  Rule 3 has `fill in`, `delete this` and `delete the one(s) you do not use`
  (round 1, finding 4). Plan D3's `replace the marker` is not an entry of its
  own: `replace` matches when a marker follows in the same sentence, and #70
  rule 3 does not name "replace" (round 2, note 1, declined). Rule 2 matches `Armature` with
  a capital A only, so a path or URL (`armature.pin`) is not a match. A marker is
  one unit, so a word inside a marker is not a match; a `fill` or `replace` after
  `#` or `-` (an anchor) is not a match. A false positive was fixed by a better
  sentence, not by a list entry.
- **D4.** The rule-2 allow-list holds nine files that state a fact about LAYUP
  that names Armature (reading A of the plan review, condition 5), each with its
  reason in `ad_allowed`. Each `Armature` line of these files was read by hand.
- **D5.** The record shapes of `mk_allowed` became `<…>` shapes, and
  `mk_allowed` was deleted. No exemption was added to `markers`: the evidence
  file writes each marker character of captured output by name (`<U+2039>`), so
  the `main` copy of the check, which CI runs on the pull request, passes it
  (round 1, finding 1).
- **D6.** The five CI copies under `docs/ci/` and `docs/templates/gitlab/` were
  deleted; LAYUP's CI is `.github/workflows/`, and its forge is GitHub.
- **D7.** `docs/templates/github/` stays, not active, and its README says so.
- **No setup step.** A step S16 in `steps.tsv` was written and then removed
  (round 1, finding 3): #70 does not ask for one, and a step that rewrites text
  with no source conflicts with REQ-018. [`setup/README.md`](../setup/README.md)
  § Check `adapted` describes the check and its known limit; the same checks
  become part of `layup setup verify` for a target later (#70 rule 5).

## Known limits

- The check reads Markdown only: comments in scripts, rows of `steps.tsv` and
  lines of workflows can still speak as the template (the plan review counted 27
  lines in `setup-check.sh`, 7 rows of `steps.tsv`, and lines in the three
  linters and `ci.yml` on `9beff4c`). Recorded in
  [`setup/README.md`](../setup/README.md) § Check `adapted`; no follow-up issue
  (the Operator's rule of 2026-09-27).
- For `fill` and `replace` before a marker, a `.` ends the sentence, so "e.g." or
  a path between the verb and the marker hides the match (round 1, note 3).
- CI restores `setup-check.sh` and `docs/setup/tests/` from `main`, so the pull
  request's own CI does not run `adapted` or its fixtures (condition 3), and it
  runs the `main` copy of `markers` on this tree, which the tree must pass too
  (round 1, finding 1). The
  evidence at landing is the local full run; after the merge the author copies the
  line `setup-check: adapted OK` of the first CI run on `main` into a comment on
  #70.
- `assets/armature-logo.jpg` and `assets/social-preview.jpg` (Armature's images)
  stay in the tree, unused by any document.

## Review round 1 and its fixes (cycle 1)

Round 1 (GPT-6 Sol on the Devin CLI, effort `xhigh`, on `53b3a99`; the record is
on #85) gave `material`, with five findings. Each fix has its red run
([`test-runs.md`](../../runs/T-79y7/test-runs.md)):

1. **A done step with no `answers.sha256` row** skipped the check of its
   answers: it is now exit 2. The stand-in record has the row of S01, and
   `work.AnswersHash` is the one home of the row (`internal/setup` writes it).
2. **A commit off `layup-setup`:** the runner reads the target's branch with
   the new call `git.Branch` (`git symbolic-ref --quiet HEAD`, a row of the
   calls table of `packages.md`); on another branch, or a detached `HEAD`, the
   step fails with no commit.
3. **A hand-off with no command** is now `fail`, before any commit; and
   `commands.sh` is written again at the end of each run, empty when no done
   step has a command, so no command of an earlier record stays.
4. **An `S01-` question that S01 does not ask** is exit 2 before any step: the
   four names of S01 are fixed. The `Q-` and `M-` rows stay the checks of S01
   and S10 (`CheckAsked`), which need their gap table and their markers.
5. **The ref of the hash row:** `sha256 inputs/answers.tsv S01- Q-`, a form that
   the ref rule of the record's block now names; the input error quotes "an
   input that changed after a step read it", as `setup.md` does.
